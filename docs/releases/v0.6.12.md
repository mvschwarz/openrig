# OpenRig 0.6.12

0.6.12 is a fix release about recovery and everyday operation, and most of it came from the community: 121 of its 206 changes are from 23 outside contributors. Restore brings back what you left running and leaves down what you stopped: an ordinary terminal seat relaunches fresh, `rig start --last` keeps a rig you took down on purpose down, and a slow Claude start ends as needing attention instead of failed. Managed compaction sends a `/compact` short enough to run again, and Claude seats now load the hooks OpenRig ships for them. You can set one seat's reasoning effort, give a team environment variables in its spec, change a seat's permission policy in place, launch a rig by its name, and read what each seat reports it costs. The CLI starts faster, and the daemon does much less work on a busy machine.

```
npm install -g @openrig/cli
```

It's built from `9e5382dd`: main at `48fe7827`, which holds 198 changes made since 0.6.11 (and five that 0.6.11 already shipped), plus eight changes merged later and picked onto it: [#1491](https://github.com/mvschwarz/openrig/pull/1491), [#1488](https://github.com/mvschwarz/openrig/pull/1488), [#1492](https://github.com/mvschwarz/openrig/pull/1492), [#1496](https://github.com/mvschwarz/openrig/pull/1496), [#1483](https://github.com/mvschwarz/openrig/pull/1483), [#1504](https://github.com/mvschwarz/openrig/pull/1504), [#1506](https://github.com/mvschwarz/openrig/pull/1506) and [#1518](https://github.com/mvschwarz/openrig/pull/1518), without #1506's one edit to an agent startup guide section this release doesn't have, and without #1518's edits to code from [#1498](https://github.com/mvschwarz/openrig/pull/1498), which isn't in this release. Nothing else merged after `48fe7827` is in this release. If something breaks for you, please open an issue.

## Before you upgrade

**Restart the daemon after upgrading the CLI.** The running daemon keeps its old build until it restarts: run `rig daemon stop`, then `rig daemon start`. Twelve database migrations run on the first start, whatever you use:
- `100` adds the typing guard's mode columns ([#1481](https://github.com/mvschwarz/openrig/pull/1481));
- `104` adds `nodes.effort_choice` ([#1209](https://github.com/mvschwarz/openrig/pull/1209));
- `105` adds two columns to `usage_samples` for Claude's client-side cost estimate ([#1233](https://github.com/mvschwarz/openrig/pull/1233));
- `107` adds the `pi_usage_entries` table ([#1237](https://github.com/mvschwarz/openrig/pull/1237)), and `108` adds two columns to it and a `pi_usage_charges` table ([#1244](https://github.com/mvschwarz/openrig/pull/1244));
- `109` makes the mode store's unique index per category, keeping every row ([#1274](https://github.com/mvschwarz/openrig/pull/1274));
- `110` adds `workflow_instances.scope_json` ([#1273](https://github.com/mvschwarz/openrig/pull/1273));
- `111` adds `rigs.env_json` and `nodes.env_json` ([#1294](https://github.com/mvschwarz/openrig/pull/1294));
- `112` adds two indexes for reading recent queue activity, about 10 to 12 MB on a long-running install's database ([#1326](https://github.com/mvschwarz/openrig/pull/1326));
- `113` adds `applied_launch_observations.daemon_opt_out` ([#1371](https://github.com/mvschwarz/openrig/pull/1371));
- `114` adds `sessions.agent_app` ([#1392](https://github.com/mvschwarz/openrig/pull/1392));
- `115` rebuilds the Slack thread map keyed by channel and thread timestamp, keeping existing rows ([#1436](https://github.com/mvschwarz/openrig/pull/1436)).

There are no migrations `102` or `106`, and no earlier migration was changed.

**The bundled openrig-core plugin goes from 0.1.9 to 0.1.13, and Claude seats now run its hooks.** A Claude seat whose plugins include `openrig-core` (every agent spec OpenRig ships selects it) now starts with `CLAUDE_CODE_PLUGIN_DIRS` pointing at OpenRig's copy, so its activity relay, compaction save and restore hooks, and refocus actually run. Before, the plugin was copied to a folder Claude Code doesn't load. It needs Claude Code 2.1.280 or later; an older Claude Code ignores the setting, and OpenRig doesn't check the version. A seat that's already running picks it up at its next launch, restore or handover ([#1344](https://github.com/mvschwarz/openrig/pull/1344)). The refocus hook may now take up to 60 seconds instead of 5, so a refocus that hangs can hold up a prompt for up to a minute ([#1475](https://github.com/mvschwarz/openrig/pull/1475)).

**Six new settings, all off except one:** `output.whoami_peers` (default 8, used only while `output.compact` is on), plus `bundle.services_enabled`, `provider.subscription_moves`, `usage.pi_cost_facts`, `usage.pi_openrouter_charge` and `transport.verify_input_box`, all false. "Off by default" below says what each does and what acts with it off. `output.compact` and `provider.usage_windows` stay off and cover more than in 0.6.11.

**Behaviour that changed:**

- **`rig start --last` leaves down a rig you stopped on purpose** with `rig down` or `rig seat stop`, and prints how to bring it back (`rig start --rigs <rig>`); `--json` carries `keptDown`. `--all`, `--rigs` and the picker are unchanged ([#1238](https://github.com/mvschwarz/openrig/pull/1238)). After `rig down`, `rig ps` and the TUI read the rig `stopped` instead of recoverable ([#1254](https://github.com/mvschwarz/openrig/pull/1254)), and the printed restore command is `rig up '<name>' --existing`, which works even when the name matches a shipped starter ([#1425](https://github.com/mvschwarz/openrig/pull/1425)).
- **An ordinary terminal seat relaunches fresh on restore** and re-runs its startup actions, instead of stopping at `awaiting-decision` on every restore after its first. A required startup file missing for such a seat now blocks the whole restore before anything launches (`required_startup_file_missing`) ([#1328](https://github.com/mvschwarz/openrig/pull/1328)).
- **Restore stops a seat whose current runtime differs from the one its snapshot started with,** before creating its terminal session, and `--fresh` doesn't bypass it ([#1190](https://github.com/mvschwarz/openrig/pull/1190)).
- **A slow start ends as needing attention, not failed.** A restored Claude seat that hasn't drawn its screen is watched for up to `runtime.readiness_timeout_seconds` (30 s by default) and then ends `attention_required` with its pane and attempted resume token kept, so a restore can take longer: up to about 27 seconds more for each seat that never starts, one after another ([#1359](https://github.com/mvschwarz/openrig/pull/1359)). A seat is described as "returned to a shell" only when the process tree shows an idle shell ([#1357](https://github.com/mvschwarz/openrig/pull/1357), [#1395](https://github.com/mvschwarz/openrig/pull/1395), [#1373](https://github.com/mvschwarz/openrig/pull/1373)), and the older restore path for rigs without pods keeps such a seat for attention instead of rolling it back ([#1364](https://github.com/mvschwarz/openrig/pull/1364)).
- **A Pi or OMP seat whose agent has exited to a bare shell reads `attention_required`** (`process_identity_mismatch`) instead of running, so `rig start` offers its rig as a restore candidate ([#1391](https://github.com/mvschwarz/openrig/pull/1391)).
- **A send to a pane in tmux copy or view mode leaves the mode once and delivers.** A pane that can't leave its mode gets no text, and the send is refused with `pane_in_mode` (HTTP 409). A person scrolled back in that pane is returned to the bottom ([#912](https://github.com/mvschwarz/openrig/pull/912), reported in [#331](https://github.com/mvschwarz/openrig/issues/331)).
- **`rig send --dangerously-interact` types exactly the bytes and keys you give it,** in any state and over every transport: a lone CR, Tab, Space or Esc acts as that key. Enter is added only when a complete answer is visibly staged in a recognised Claude Code or Codex input box; anywhere else, put CR in the payload yourself ([#1366](https://github.com/mvschwarz/openrig/pull/1366)).
- **Managed `/compact` is kept to 600 characters, sent only to an idle seat, and reported separately.** Since 0.6.10 the managed command had grown long enough that Claude Code took it as pasted text, so it didn't run while the attempt read as delivered. The rest of the instructions move into the restore map and the restore request. `rig compact` and `rig compact --state` show a separate `compact` result: `submitted, unconfirmed` (it reached the seat; that isn't proof compaction ran), `uncertain` (not replayed) or `not sent`. A running draft-aware seat with no recorded pane is refused with `pane_unknown_protected`: `rig compact` exits 1 (was 2) and the route answers 409 (was 502). Over the shared transport, a write that throws without a code makes `rig send` exit 1 with HTTP 409 instead of 2 with 500 ([#1483](https://github.com/mvschwarz/openrig/pull/1483), towards [#27](https://github.com/mvschwarz/openrig/issues/27)).
- **`rig queue update` refusals you can fix answer HTTP 400 and exit 1,** not 500 and exit 2: eleven error codes for closure fields, `blocked_on` or wake options where they can't be stored, and a watchdog that isn't live or targets someone else. `blocker_not_found`, `blocker_not_live` and `blocker_malformed` still exit 2 ([#1319](https://github.com/mvschwarz/openrig/pull/1319)).
- **`rig ask` exits 1 for an unknown or ambiguous rig** instead of 0 ([#1202](https://github.com/mvschwarz/openrig/pull/1202)).
- **`rig add`, single-seat `rig launch` (including `--retry-startup-from`) and `rig launch --seats` wait up to 120 seconds** for the daemon instead of 5. A timeout there still isn't a rollback, so check `rig ps` before running it again ([#1287](https://github.com/mvschwarz/openrig/pull/1287), [#1271](https://github.com/mvschwarz/openrig/pull/1271)).
- **A runtime's `--version` check gives up after 30 seconds.** At daemon start a hung probe no longer keeps the daemon from listening, and `rig bootstrap` now blocks on a runtime that is installed but fails or times out its check, which it reports apart from one that's missing ([#1211](https://github.com/mvschwarz/openrig/pull/1211)). `rig up`'s preflight fails a Claude, Codex or OMP check that doesn't answer within 30 seconds (a warning for Pi), and stopping the daemon ends the probes it started ([#1301](https://github.com/mvschwarz/openrig/pull/1301)).
- **Claude login detection is narrower.** Only a current refusal (`Not logged in · Please run /login`, `Login expired · Please run /login` or `OAuth token revoked · Please run /login`) reads `login_required`. The "Not logged in" footer alone no longer does, so a seat signed in through a gateway starts, resumes and restores normally ([#1417](https://github.com/mvschwarz/openrig/pull/1417), reported in [#1405](https://github.com/mvschwarz/openrig/issues/1405)).
- **The `fable` model alias now names `claude-fable-5-1`,** so a `fable` pin on a seat running `claude-fable-5` raises a divergence notice. A Claude pin ending `[1m]` no longer does when the seat runs that model ([#1482](https://github.com/mvschwarz/openrig/pull/1482)). Pinned Pi seats are now checked, and a Pi thinking-level suffix such as `:high` doesn't count as a divergence ([#1349](https://github.com/mvschwarz/openrig/pull/1349), [#1403](https://github.com/mvschwarz/openrig/pull/1403)).
- **A custom permission policy saved with Windows (CRLF) line endings now takes effect.** It used to fail to parse, so the seat fell back to the advisory floor; now it resolves to its declared posture at the next launch or restore ([#1402](https://github.com/mvschwarz/openrig/pull/1402)).
- **`rig bundle create` refuses harness login files** (`.claude/.credentials.json`, `.codex/auth.json`, `.pi/agent/auth.json`) anywhere in an agent folder or carried project. An existing archive holding one without a record now fails verify, unpack and install; install answers 400 even with `--force`. "Off by default" covers the opt-in ([#1488](https://github.com/mvschwarz/openrig/pull/1488)).
- **`rig scope mission create` writes `status: planned`,** which keeps a new mission out of the project's proof rollup until you set it `active` ([#1289](https://github.com/mvschwarz/openrig/pull/1289)). With `--workspace <project>` it creates the mission inside that project, under its declared `missions.root`, which now wins over a `missions/` folder for every command that reads missions ([#1430](https://github.com/mvschwarz/openrig/pull/1430), reported in [#70](https://github.com/mvschwarz/openrig/issues/70)).
- **On Linux and macOS, the daemon runs tmux directly instead of through `/bin/sh`.** Set `OPENRIG_TMUX_SHELL=1` when starting the daemon to keep the old path ([#1241](https://github.com/mvschwarz/openrig/pull/1241)).
- **The daemon writes Codex's `config.toml` only when a Codex seat exists or launches,** so a daemon that never runs Codex leaves `~/.codex/config.toml` alone ([#1297](https://github.com/mvschwarz/openrig/pull/1297)).
- **Slack:** a person's new message in a rig's own mapped channel now goes to that rig's representative (or a seat named with `--inbound`), and every seat post's sender line names the machine (`from <seat> on <host id>`), on one machine too ([#1436](https://github.com/mvschwarz/openrig/pull/1436)). The app manifest asks for one more scope, `users:read` ([#1433](https://github.com/mvschwarz/openrig/pull/1433)).
- **`rig remove` and `rig shrink` keep a seat that receives work while it's being stopped:** the late work goes to your `--fallback`, or the stopped seat is kept and the command answers 409 with the work listed ([#1459](https://github.com/mvschwarz/openrig/pull/1459)). A stale `rig unclaim` that would detach the seat's newer occupant is refused with 409 `session_not_current` ([#1379](https://github.com/mvschwarz/openrig/pull/1379)).
- **`rig seat status` reads `Typing guard: on (hold)` for hold,** and its JSON's `desired` and `effective` booleans now mean hold only ([#1481](https://github.com/mvschwarz/openrig/pull/1481)).
- **`rig usage top` no longer counts a new conversation, or a reset window, as burn.** Tokens and rates are measured within one history and one window, so figures can drop and rankings change ([#1348](https://github.com/mvschwarz/openrig/pull/1348), reported in [#774](https://github.com/mvschwarz/openrig/issues/774); [#1473](https://github.com/mvschwarz/openrig/pull/1473)).
- **The execution view binds a queue row to a mission by its exact `mission:` tag first** ([#1304](https://github.com/mvschwarz/openrig/pull/1304)), and a `slice:` tag can name a slice by its SPEC `id:` as well as its folder ([#1331](https://github.com/mvschwarz/openrig/pull/1331)).

## Highlights

**Restore and launch.**
- **`rig launch` takes a rig's name as well as its ID,** locally and with `--host`. A name two active rigs share stops before anything is sent and lists their IDs (`rig_ambiguous`). Before, it took only an ID, and a name failed with not found ([#1312](https://github.com/mvschwarz/openrig/pull/1312)).
- **A Codex seat that forks a conversation keeps its startup context when the new conversation's ID arrives late.** The launch waits up to the readiness timeout for a verified child; if none arrives, the seat stops at `attention_required`, and `rig seat continue <seat>` delivers its role once ([#1438](https://github.com/mvschwarz/openrig/pull/1438), reported in [#317](https://github.com/mvschwarz/openrig/issues/317)). A handover to a forked Codex conversation completes with the ID marked pending instead of failing ([#1216](https://github.com/mvschwarz/openrig/pull/1216)).
- A seat whose startup failed for a recoverable readiness reason becomes ready after a successful send or capture ([#1236](https://github.com/mvschwarz/openrig/pull/1236), towards [#7](https://github.com/mvschwarz/openrig/issues/7)). A periodic snapshot taken while `rig down` was stopping a rig no longer replaces the complete pre-down snapshot ([#1147](https://github.com/mvschwarz/openrig/pull/1147)).

**Set up a seat without touching the spec.**
- **Set one seat's reasoning effort:** `rig seat set-effort <seat> --effort <level> --reason "<why>"` (or `--clear`) saves it, and it's used at the seat's next launch, restore, handover or in-place Codex restart; nothing restarts. `rig seat effort <seat>` reports what was requested, what's saved, what the running process was launched with and what the session recorded ([#1209](https://github.com/mvschwarz/openrig/pull/1209)).
- **Change an existing seat's permission policy:** `rig policy apply <policy> --seat <seat> --reason "<why>"` stores it for the seat's next restore, resume or launch. The running agent and the spec file don't change ([#1285](https://github.com/mvschwarz/openrig/pull/1285)).
- **Give a team environment variables in its spec:** an `env:` block on the rig and on any member in `rig.yaml` reaches every seat, including Claude Code's cleared environment, carries into restores and handovers, and `rig export` writes it back. `rig up <spec> --env KEY=VALUE` adds a value for one launch. Names match `^[A-Z_][A-Z0-9_]*$`, and `OPENRIG_*` is reserved. **The values aren't secret:** they're stored in OpenRig's database and snapshots and copied by export and bundles ([#1294](https://github.com/mvschwarz/openrig/pull/1294)).

**Compaction and hooks.** Besides the shorter managed `/compact` and the plugin hooks above: automatic compaction ignores a context reading taken before a seat was stopped, replaced, handed over or restarted ([#1365](https://github.com/mvschwarz/openrig/pull/1365)), and with managed compaction on, Claude sessions OpenRig launches carry `idleCompaction: false`, so Claude Code 2.1.290 or later doesn't compact them on its own while idle ([#1282](https://github.com/mvschwarz/openrig/pull/1282)). A seat can give a slow refocus more time with `OPENRIG_REFOCUS_BUDGET_MS`, from 4500 (the default) to 52000 ms ([#1475](https://github.com/mvschwarz/openrig/pull/1475)).

**Queue rows that say what happened.**
- `rig queue update <id> --summary "<text>"` on its own corrects a row's subject in any state ([#1270](https://github.com/mvschwarz/openrig/pull/1270), reported in [#1040](https://github.com/mvschwarz/openrig/issues/1040)).
- `rig queue update <id> --state <closing state> --resolution "<outcome>"` stores the outcome on the row, `rig queue show` returns it, and a later fallback adds its line instead of erasing it ([#1292](https://github.com/mvschwarz/openrig/pull/1292)).
- `rig queue show <id> --full` on a closed row adds `closingTransition`: its state, reason, target, who closed it, when, and the closing note ([#1290](https://github.com/mvschwarz/openrig/pull/1290)).
- An agent with no shell can hand work to the team through `rig mcp serve`, which gains five queue tools (`rig_queue_create`, `rig_queue_show`, `rig_queue_list`, `rig_queue_claim` and `rig_queue_update`), acting as the seat named by `OPENRIG_SESSION_NAME`. Nothing wakes such an agent; it sees new work when it checks ([#1441](https://github.com/mvschwarz/openrig/pull/1441)).

**What a seat costs.** `rig usage cost [--seat <session>] [--json]` shows what each seat's harness reports about cost beside its tokens: for Claude, the status line's own estimate for the current session (labelled an estimate, not an invoice); for Codex, tokens and a note that Codex reports no cost. A missing figure reads "not reported", never $0. It needs no setting ([#1233](https://github.com/mvschwarz/openrig/pull/1233)), and the TUI's new System → Cost page shows the same lines ([#1261](https://github.com/mvschwarz/openrig/pull/1261)).

**Faster.** The CLI loads only the command being run and turns on Node's compile cache, so `rig queue list` and `rig ps` start several times faster in the author's measurements ([#1380](https://github.com/mvschwarz/openrig/pull/1380)). The daemon runs tmux without a shell, captures up to 24 transcripts in one tmux call, skips reading terminals that haven't changed, and reads queue activity and obligations with far fewer queries ([#1241](https://github.com/mvschwarz/openrig/pull/1241), [#1242](https://github.com/mvschwarz/openrig/pull/1242), [#1262](https://github.com/mvschwarz/openrig/pull/1262), [#1263](https://github.com/mvschwarz/openrig/pull/1263), [#1326](https://github.com/mvschwarz/openrig/pull/1326), [#1369](https://github.com/mvschwarz/openrig/pull/1369), [#1384](https://github.com/mvschwarz/openrig/pull/1384), [#1389](https://github.com/mvschwarz/openrig/pull/1389); reported in [#161](https://github.com/mvschwarz/openrig/issues/161) and [#308](https://github.com/mvschwarz/openrig/issues/308)). The timings are the authors' own.

## Off by default, and what acts anyway

- **`output.compact`** (`OPENRIG_OUTPUT_COMPACT`, from 0.6.11) now also shortens `rig queue show` and `rig queue transitions` (`--full` prints everything; `rig queue transitions --full` is new) ([#1224](https://github.com/mvschwarz/openrig/pull/1224)), and bounds `rig whoami --json` peers to `output.whoami_peers` (new, default 8), connected peers first; `--all-peers` lists everyone ([#1225](https://github.com/mvschwarz/openrig/pull/1225)). Over SSH `--host`, the note's full-list command now names the host ([#1248](https://github.com/mvschwarz/openrig/pull/1248)).
- **`provider.usage_windows`** (`OPENRIG_PROVIDER_USAGE_WINDOWS`, daemon, from 0.6.11) now also shows Claude's 5-hour and weekly windows from the seats' status lines in `rig provider status`, with `--provider codex|claude` to limit a refresh ([#1197](https://github.com/mvschwarz/openrig/pull/1197)); each seat's configured account ([#1235](https://github.com/mvschwarz/openrig/pull/1235)); and, with `--all-hosts` or `--hosts <ids>`, every registered machine's windows, listed once per allowance and never added up ([#1246](https://github.com/mvschwarz/openrig/pull/1246)). **A Claude account's current availability always reads `unknown`,** because nothing links a seat's reading to the login it used; each window still shows as that seat's reading ([#1504](https://github.com/mvschwarz/openrig/pull/1504)). The TUI's System → Usage and Usage · all hosts pages are always listed and, with the setting off, say how to turn it on ([#1243](https://github.com/mvschwarz/openrig/pull/1243), [#1259](https://github.com/mvschwarz/openrig/pull/1259)).
- **`usage.pi_cost_facts`** and **`usage.pi_openrouter_charge`** (`OPENRIG_USAGE_PI_COST_FACTS`, `OPENRIG_USAGE_PI_OPENROUTER_CHARGE`): Pi's own cost estimate in `rig usage cost`, counted once with a fork's inherited entries kept apart ([#1237](https://github.com/mvschwarz/openrig/pull/1237)), and OpenRouter's actual charge beside it, never added to it. With both on, the Pi runner asks OpenRouter for each request's charge with the key OpenRig already gives the seat ([#1244](https://github.com/mvschwarz/openrig/pull/1244)). A Pi seat reads both switches when it launches or resumes, so a change takes effect then; what was recorded stays visible.
- **`provider.subscription_moves`** (`OPENRIG_PROVIDER_SUBSCRIPTION_MOVES`): a record of moves of a Codex home's seats between subscriptions, `rig provider moves [--home|--seat|--limit]`, `rig provider moves show <id>` and `rig provider moves record --file <json|->`, plus a section of the `openrig-user` skill for an agent a person asks to manage subscriptions. While it's off, the commands exit 1 and the routes answer 409 ([#1450](https://github.com/mvschwarz/openrig/pull/1450)).
- **`bundle.services_enabled`** (`OPENRIG_BUNDLE_SERVICES_ENABLED`): a bundle carries its declared Compose file, `rig bundle inspect` shows each service before anything runs, and `rig up` and `rig bootstrap` install it into a lasting target folder ([#1474](https://github.com/mvschwarz/openrig/pull/1474)).
- **`transport.verify_input_box`** (`OPENRIG_TRANSPORT_VERIFY_INPUT_BOX`): a `--verify` send to Claude Code or Codex reads verified only when the text was seen in the input box and the box was empty after Enter. It only reports; nothing is retried. Multi-line sends and wakes to Claude Code stay unconfirmed ([#1267](https://github.com/mvschwarz/openrig/pull/1267)).
- **Per seat:** `rig seat set-typing-guard <seat> --mode draft-aware --reason "<why>"` checks the input box before typing and before Enter, and holds or refuses a message instead of typing over someone's unsent text; nothing retries it. `--mode hold` is the existing on, and `--mode off` the default ([#1481](https://github.com/mvschwarz/openrig/pull/1481)).
- **Per bundle:** `rig bundle create --include-login-files` includes those login files only when recipients should have them and the login's owner agrees, and records their paths as `included_login_files` ([#1488](https://github.com/mvschwarz/openrig/pull/1488)).
- **Daemon environment:** `OPENRIG_TMUX_CONTROL=1` sends the daemon's routine tmux commands through one long-lived control client ([#1383](https://github.com/mvschwarz/openrig/pull/1383)).
- **What acts with every setting off:** the twelve migrations; the plugin hooks in Claude seats; Claude's cost estimate is recorded from the status line, and `rig usage cost` and the TUI's Cost page work; a Pi `models.json` notice can report a provider key's presence instead of unknown, because `models.json` is now read the way Pi reads it ([#1244](https://github.com/mvschwarz/openrig/pull/1244)); and the draft-aware guard's shared send and startup code runs for every seat.

## Dependency and install-script changes

- **npm dependencies:** the daemon now declares `string-width` (`^8.3.0`), which was already in the installed tree, so the lockfile adds no package ([#1481](https://github.com/mvschwarz/openrig/pull/1481)). The daemon package exports two more entry points, `./composer-prompts` ([#635](https://github.com/mvschwarz/openrig/pull/635)) and `./workflow-scope` ([#1273](https://github.com/mvschwarz/openrig/pull/1273)). The Node requirement is unchanged (`node >=22`).
- **Install scripts:** unchanged. The package's only lifecycle script is still `postinstall: node scripts/check-abi.mjs`.
- **Database:** the twelve migrations above.

## Everything else since 0.6.11

**Seats, launch and restore.**
- A failed process-lineage check says what it found (for example, that the running Codex was launched with a different conversation than the seat records), instead of blaming the pane's foreground label ([#1398](https://github.com/mvschwarz/openrig/pull/1398)). `rig reconcile-session` no longer reports a runtime drift for a pane reading `sh` when Claude or Codex is running in it ([#1395](https://github.com/mvschwarz/openrig/pull/1395), reported in [#1199](https://github.com/mvschwarz/openrig/issues/1199)); a Codex seat started through a shell wrapper isn't reported as returned to a shell while it starts ([#1373](https://github.com/mvschwarz/openrig/pull/1373), reported in [#79](https://github.com/mvschwarz/openrig/issues/79)).
- When a Claude seat's startup prompt is still unsent, the launch presses Enter up to twice, each time only while the box holds exactly that prompt, and more Claude footers are recognised, so fewer healthy launches warn "Startup submission unverified" ([#1295](https://github.com/mvschwarz/openrig/pull/1295)).
- In a Claude seat started with a permission mode, Shift+Enter inserts a newline when tmux's `extended-keys` is on: the launch passes the pane's `TERM_PROGRAM` and `TERM_PROGRAM_VERSION` to Claude ([#1399](https://github.com/mvschwarz/openrig/pull/1399)). The getting-started guide says how to add a newline when Shift+Enter submits ([#1404](https://github.com/mvschwarz/openrig/pull/1404)).

## How it was tested

- **The final package:** 4,438 files and 7,594,843 bytes (sha256 `c16c934850d44139cd6b0cce400e84f976db448766fa15dccf8213cdc721598c`),
  built from `9e5382dd` and stamped with it. An independent read matched every file against the release's source.
- **Compared with 0.6.11:** 206 changes; the package grows from 4,208 files and 7,102,511 bytes to 4,438 files and 7,594,843 bytes.
- **The source:** an independent read confirmed that the release's source is exactly main at `48fe7827` plus the first six picked changes, each identical to its merged original; the same read checked [#1506](https://github.com/mvschwarz/openrig/pull/1506), the seventh, and [#1518](https://github.com/mvschwarz/openrig/pull/1518), the eighth, at the sites where each was picked without its edits that depend on [#1498](https://github.com/mvschwarz/openrig/pull/1498). That's a check of what's in the release, not of how it behaves.
- **Each change** ran the repository's automated tests, merged into the main of its day, before it merged. On the release commit itself, 344 selected tests, the build, the CLI type check, the generator and the docs and audit checks passed, and the packaged help ran for three commands; that's a selected set, not the full test suite.
- **Upgraded installs:** three long-running Linux installs moved to this release, two from the released 0.6.11 and one from a pinned 0.6.11 build. Each kept its queue rows and their contents, its running agent processes and its team layout, and each database passed its integrity check. That doesn't show that each agent's own conversation carried on.
- **Teams at work after the upgrade:** two Codex seats started through the shipped launcher sent messages, handed work off and were woken in both directions. A daemon restart in the middle of work kept a parked row and a deliberately stopped seat as they were. The delivery and idle-detection checks matched 0.6.11's except for one deliberate change, the clearer message when pressing Enter fails (163 of 164, against 164 of 164). A Pi agent launched, replied and received its messages; when woken for work, it answered early, sent a message to itself and didn't close its row. The agents were Claude Code 2.1.299 and 2.1.303 and Codex 0.163.
- **A Claude agent through ordinary prompts, compaction and restore, with the plugin hooks loaded:** six managed compactions were started by command, not by the automatic threshold. Four compacted and restored: one of them needed a person to point the agent to its restore map, and another needed seven approvals. Two failed, for different reasons (see Known issues). After compaction, refocus didn't meet its check: for active work its trace reported a gap after timing out, and for parked work it showed a general fallback. No prompt stall from the hooks showed up in the samples taken ([#1344](https://github.com/mvschwarz/openrig/pull/1344)), which doesn't show there's none. A Codex seat compacted natively; Codex refocus wasn't run.
- **A full snapshot restore** brought back the three seats meant to be running and kept the stopped seat stopped, but reported `partially_restored` overall, with that stopped seat left awaiting a decision. Work and each conversation after the restore weren't checked.
- **The first-user check, on a Mac with fresh user accounts:** a person using Claude Code as their own agent installed OpenRig, reached a running team and got a useful change on a local branch, with some one-off approvals along the way. A person using Codex got the same result end to end after a workaround: Codex ran with `--no-daemon`, and the person answered 19 one-off approvals. Running both people on one Mac found the cross-user problem in Known issues. The Mac had been used before, so this isn't a brand-new-machine result.
- **Sharing a team through the registry:** a submission passed the registry's real pull-request check. We opened and closed the pull request for the person, so a person's own GitHub sign-in and submission weren't run.
- **Compared with 0.6.11,** the paths checked showed no problem newly introduced by this release. That covers the paths compared, not everything. Where problems did show up (the Mac cross-user routing and the two compaction failures), the code involved matches 0.6.11's, but 0.6.11 wasn't run alongside to compare.
- **Our own team's install** moved to this release, stalled while its host was under heavy load, and was put back on 0.6.10. The evidence points to the host running short of resources, but whether the stall came from this release isn't established. The install then moved to this release again from a fresh backup: its database passed its integrity check, its running agent sessions were kept, and a queue round trip worked at normal load. That shows a good start, not how it holds up over time.
- **Not run on this release:** a working day of use, the automatic compaction threshold and slow leaks (these checks were deliberate events over a few hours); a team with one machine still on an older release; the 30-second `--verify` wait from the package; a shared-server restart on a Mac; a brand-new Mac; native Windows; the installed-package scenarios on this exact release (they ran on an earlier build); Codex refocus and its packet; a real Codex fork; and a restore after a reboot. Other behaviour described in these notes comes from each change's own tests and reviews. **Slack wasn't run on this release:** the gate question ([#1143](https://github.com/mvschwarz/openrig/pull/1143)), one app across several machines ([#1436](https://github.com/mvschwarz/openrig/pull/1436)) and the standing Slack checks ship without a native run, and they're checked in real use after release.

## Known issues

- **On a Mac with more than one user account, a second user's `rig` commands can reach the first user's OpenRig.** In the first-user check, the second person's ordinary commands reached the first person's daemon on its default port (7433), read one of its queue rows and sent a request to the first person's operator, which ran its checks and refused to work on the other user's private project. Running each user's daemon on its own port let both people work, but it doesn't keep them apart. The code involved matches 0.6.11's; 0.6.11 wasn't run to compare. It's being diagnosed for 0.6.13.
- **Managed compaction failed in two of six runs on this release.** In one, saving the agent's recap needed a one-off approval, so the agent stopped at the approval and the compaction was never sent. In the other, the restore map was ready about ten seconds after the 120-second preparation deadline, so the compaction wasn't sent. The code involved matches 0.6.11's; 0.6.11 wasn't run to compare. Confirm that a compaction ran as described in the next item.
- **After a compaction, refocus may not show the agent's current work.** For active work, its trace can time out and report a gap; for parked work, it can show a general fallback. The code involved matches 0.6.11's; 0.6.11 wasn't run to compare.
- **The one full snapshot restore run on this release reported `partially_restored`:** the three seats meant to be running came back, and a deliberately stopped seat was left awaiting a decision.
- **Managed compaction's command budget is 600 characters,** set from one comparison on Claude Code 2.1.282 (792 characters ran as a command, 850 didn't), and a later Claude Code could move that line. Nothing confirms compaction ran; read `submitted, unconfirmed` as reached, and confirm by the restore request or the drop in context ([#1483](https://github.com/mvschwarz/openrig/pull/1483)).
- **Two plugin hook runs for the same seat aren't serialized:** if a harness overlaps them, a post-compaction record can be lost or a refocus delivered twice. Overlapping runs weren't tested, and the samples that showed no prompt stall don't show that overlaps or stalls can't happen ([#1344](https://github.com/mvschwarz/openrig/pull/1344), [#1475](https://github.com/mvschwarz/openrig/pull/1475)).
- **`rig policy current` and plain `rig ps` don't show a policy stored with `rig policy apply --seat`;** `rig seat status` and pod-aware export do ([#1285](https://github.com/mvschwarz/openrig/pull/1285)).
- **`env:` and `--env` values aren't secret,** and members added later with `rig grow` can't carry a member-level `env:` ([#1294](https://github.com/mvschwarz/openrig/pull/1294)).
- **`rig up --env` is not forwarded for flat-node specs or v1 bundles,** although the launch may succeed. Do not rely on the flag for those formats in this release ([#1294](https://github.com/mvschwarz/openrig/pull/1294)).
- **A fresh handover of a Claude seat in the classic renderer can report `complete` before the new Claude is ready,** because the readiness check can match the previous occupant's text still in the pane, so the handover packet may be typed before the successor starts. 0.6.11 has the same behaviour. Until it's corrected, check that the successor read its packet ([#1544](https://github.com/mvschwarz/openrig/issues/1544)).
- **One Slack app across machines was simulated in one process, never run on two real machines.** Relayed events are trusted from the calling daemon, a relay that keeps being refused is retried with no limit, `rig slack verify` on the hub doesn't check relayed channels, and an answer from a seat other than the one the message reached still posts at the top level ([#1436](https://github.com/mvschwarz/openrig/pull/1436)).
- **The draft-aware typing guard waits for idle inside the seat's delivery lease** when the input box is empty, which can delay other work for that seat (not measured), and it can't guard text a person types in the instant before OpenRig types ([#1481](https://github.com/mvschwarz/openrig/pull/1481)).
- **A Claude account's availability always reads `unknown` with usage windows on,** until a seat's reading can be linked to its login ([#1504](https://github.com/mvschwarz/openrig/pull/1504)).
- **A restore starts seats one after another,** so each seat that never draws its screen adds about the readiness timeout ([#1359](https://github.com/mvschwarz/openrig/pull/1359)).
- **A delivery already in transport when its watchdog stops still completes,** with its records ([#1325](https://github.com/mvschwarz/openrig/pull/1325)).
- **The recent-activity index costs about 10 to 12 MB** on a long-running install, and each new transition writes one more index entry ([#1326](https://github.com/mvschwarz/openrig/pull/1326)).
- **The `openrig-user` skill's subscription section mentions apps that don't ship in this release;** don't look for them ([#1450](https://github.com/mvschwarz/openrig/pull/1450)).
- **With `bundle.services_enabled` on, `rig up <file>.rigbundle` installs into the current folder when you don't give `--target`** ([#1474](https://github.com/mvschwarz/openrig/pull/1474)).
- **A send to a seat can still be refused for a quoted permission prompt** that isn't really waiting; this is unchanged from earlier releases.
- **Carried from 0.6.11:**
  - **`rig seat restart --keep-conversation` supports Linux only,** and its native result hasn't been re-run on 0.6.12.
  - **The rig status API can call a running rig `blocked` because of one seat that isn't running:** it folds a restore forecast into current status ([#1141](https://github.com/mvschwarz/openrig/pull/1141)).
  - **A Codex seat can keep reading as at its usage limit** in a constructed screen case that hasn't been seen in a real session ([#1185](https://github.com/mvschwarz/openrig/pull/1185)).
  - **After `rig scope slice create` says it couldn't verify membership, the slice was kept.** Check `mission.yaml` before creating it again ([#1007](https://github.com/mvschwarz/openrig/pull/1007)).
  - **The first-install check is still limited:** on this release it ran on a Mac that had been used before, with fresh user accounts, for Claude Code and Codex (see How it was tested). A brand-new Mac and native Windows haven't been checked, and Linux was last checked with 0.6.11.
  - A second session in the same folder can misread a running team; the operator can point a person without a display at the shared dashboard without saying how to open it; the skill installer may not select Claude Code when it detects another agent; `rig doctor` checks both harnesses; `rig tui --shared` attaches on the default tmux server; a team's first steps can still ask for approval; a seat waiting at a permission prompt shows no product notice of its own; a launched team writes into its working folder; a resumed Claude seat can't be confirmed after `/clear`, an in-process `/resume` or a hand-started process; Codex team seats don't ask before lifecycle commands; the send gate trusts the latest recorded hook; and after a restart `rig status` shows `Kernel: skipped`.
  - A Claude Code seat whose permission request was approved automatically can still read "needs input"; the Codex case is fixed ([#943](https://github.com/mvschwarz/openrig/pull/943), [#896](https://github.com/mvschwarz/openrig/issues/896)).
  - Slack missed-message recovery covers the default channel only, and private channels and direct messages aren't supported targets.
  - Older issues, as in 0.6.11: the starter's Codex reviewer needs a Codex newer than 0.145; a restore can report a problem with a seat that works ([#273](https://github.com/mvschwarz/openrig/issues/273)); a `claude` alias defined only in a nushell rc doesn't resolve; after a reboot, start the daemon with `rig daemon start` and bring your rig back with `rig up <name> --existing`; the web UI's file preview runs scripts, so preview only files you trust; browser access isn't complete browser isolation; and Codex network inside the sandbox hasn't been checked with real logins, managed policy bundles or on Linux.
